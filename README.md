# เว็บไซต์แนะนำอุทยานสิ่งแวดล้อมนานาชาติสิรินธร

หน้าเว็บตัวอย่างพร้อมภาพประกอบ แผนผังแนะนำแหล่งเรียนรู้ เส้นทาง กิจกรรม และระบบรับคิวกิจกรรมส่วนกลาง 1–100 ไม่ต้องสมัครสมาชิกและไม่มีฐานข้อมูลบัญชีผู้ใช้

## เปิดดูแบบเร็ว

เปิดไฟล์ `../index.html` ในโฟลเดอร์ outputs ได้เลย เป็นพรีวิวหน้าตาเว็บแบบออฟไลน์ ปุ่มรับคิวจะยังใช้ไม่ได้ในพรีวิวไฟล์ เพราะคิวร่วมต้องทำงานผ่านเซิร์ฟเวอร์

## ไฟล์ที่ให้มา

- `public/` หน้าเว็บ ไฟล์ CSS/JavaScript และรูปภาพตัวอย่างทั้งหมด
- `server.js` เว็บเซิร์ฟเวอร์และ API สำหรับข้อมูลกับระบบคิว
- `lib/database.js` สร้างและเติมข้อมูลตั้งต้นใน SQLite อัตโนมัติเมื่อเริ่มเว็บ
- `data/sirindhorn.sqlite` ฐานข้อมูลตัวอย่างที่มีข้อมูลหน้าเว็บและตารางคิวว่าง
- `database/initial-data.sql` สคริปต์ SQL สำหรับสร้างตารางและข้อมูลเนื้อหาตัวอย่างใน SQLite
- `package.json` ข้อมูล runtime และคำสั่งเริ่มเว็บ

เมื่อขึ้นโฮสต์จริง หากฐานข้อมูลยังไม่มี ระบบสร้างตารางและข้อมูลตัวอย่างให้เอง ไฟล์ฐานข้อมูลใน ZIP มีไว้ให้เปิดดู/ทดลองในเครื่อง และไม่จำเป็นต้อง commit เข้า GitHub; โฮสต์ควรเก็บฐานข้อมูลที่สร้างขณะทำงานไว้บน persistent disk

ไฟล์ `database/initial-data.sql` ใช้กับฐานข้อมูลใหม่/ว่างเท่านั้น และควรรันครั้งเดียว เพราะมีคำสั่งเพิ่มข้อมูลตัวอย่าง

## เปิดเว็บและระบบคิวในเครื่อง

ต้องติดตั้ง Node.js 22.13 ขึ้นไป แล้วเปิดโฟลเดอร์นี้ใน VS Code จากเมนู Terminal → New Terminal รัน:

```powershell
npm start
```

จากนั้นเปิด `http://localhost:3000` หยุดเว็บได้ด้วย `Ctrl+C` ในหน้าต่างเทอร์มินัล

## การทำงานของคิว

- ผู้เข้าชมกดรับคิวได้โดยไม่ล็อกอิน ระบบออกหมายเลขต่อกันตั้งแต่ 1 ถึง 100 ตามเวลาที่รับคำขอ
- รับได้หนึ่งคิวต่อเบราว์เซอร์ต่อวัน โดยใช้รหัสสุ่มใน local storage เพื่อกันการกดซ้ำ ไม่เก็บชื่อหรือข้อมูลส่วนบุคคล
- คิวเริ่มนับใหม่ตามวันที่ประเทศไทย ฐานข้อมูลเก็บวัน หมายเลขคิว และรหัสสุ่มเท่านั้น
- ถ้าล้างข้อมูลเบราว์เซอร์หรือเปลี่ยนอุปกรณ์ ระบบจะมองเป็นผู้เข้าชมใหม่ คิวนี้จึงเหมาะกับเดโม/กิจกรรมทั่วไปที่ไม่ต้องยืนยันตัวตน
- SQLite ใช้ได้กับเซิร์ฟเวอร์ Node.js หนึ่ง instance ที่มี persistent disk หากเปิดหลาย instance แยกฐานข้อมูล คิวจะไม่เป็นชุดเดียวกัน

## เทียบกับแผนภาพระบบที่ทำไว้

ภาพรวมสอดคล้องแบบย่อ: ผู้เข้าชมส่งคำขอดูข้อมูลหรือรับคิวมายังเว็บไซต์; เว็บไซต์อ่านข้อมูลแหล่งเรียนรู้และบันทึกหมายเลขคิวลง SQLite; จากนั้นส่งข้อมูล/หมายเลขคิวกลับไปแสดงแก่ผู้เข้าชม ไม่มีขั้นตอนสมัครหรือเข้าสู่ระบบ แผนผังจุดเรียนรู้ในเว็บเป็นภาพประกอบ ไม่ใช่พิกัดสำรวจจริง

## เอาขึ้นเซิร์ฟเวอร์

ใช้โฮสต์ที่รัน Node.js ได้และมีพื้นที่ persistent disk สำหรับเก็บ `data/sirindhorn.sqlite` ตั้งคำสั่งเริ่มเป็น `npm start` และให้โฮสต์กำหนดตัวแปร `PORT` ตามที่บริการรองรับ แนะนำให้ใช้หนึ่ง instance เพื่อให้คิวกลางตรงกันทุกคน สามารถกำหนดจำนวนคิวไม่เกิน 100 ด้วยตัวแปร `QUEUE_CAPACITY` (ค่าเริ่มต้น 100)

ตัวอย่างบน Render: อัปโหลดไฟล์ในโปรเจกต์เข้า GitHub repository แล้วสร้าง **Web Service** จาก repository นั้น ตั้ง Build Command เป็น `npm install`, Start Command เป็น `npm start`; เพิ่ม persistent disk ที่ `/opt/render/project/src/data` และใช้หนึ่ง instance จากนั้น Deploy แล้วเปิด URL ที่ Render แสดงให้ บริการฟรีของ Render ไม่มี persistent disk จึงไม่เหมาะกับคิวที่ต้องเก็บต่อเนื่อง

โฮสต์เว็บแบบ static อย่างเดียวไม่พอสำหรับระบบคิว เพราะไม่มี API และฐานข้อมูลส่วนกลาง อย่าลบหรือรีเซ็ตโฟลเดอร์ `data/` ระหว่างใช้งานจริง และควรเปิด HTTPS บนโดเมนที่นำไปใช้
